How to use useState?

State is data that belongs to a component. When you change it with the setter function, React re-renders and the screen updates.

Use setCount((prev) => ...) whenever the new value depends on the old value. Also, name the function after what it does: a function called incraseCounter that subtracts 4 is confusing.

How to use useEffect (timer with cleanup)?

useEffect runs code after the component is shown on screen. Anything you start (timer, listener) must be stopped in the cleanup function.

The dependency array decides when it runs

How to use useRef?

A ref holds a value that stays between renders. Changing it does not re-render. Most common use: grab a DOM element (focus an input, change its style).

Second use: remember a value without re-rendering

Start with useRef(null). In the notes it was useRef(() => {}), which works but is not the convention. .current points to the element only after the first render.

How to use useMemo?

useMemo remembers the result of a calculation and recalculates only when its dependencies change. Click Increment below and "Calculation done" will not print again.

Use useMemo only when the calculation is expensive, for example filtering thousands of products. For small work it adds more cost than it saves.

How to use useCallback?

Every render creates a new function. If you pass that function as a prop, the child sees a "changed" prop and re-renders. useCallback keeps the same function, and memo makes the child skip renders when props are unchanged. You need both.

Without memo on the child, useCallback changes nothing you can see. If a function uses state or props, put them in the dependency array.

How to use useReducer?

useReducer manages complex state logic. You dispatch an action, and a reducer function decides the new state.

  • useState for simple state.
  • useReducer for complex state with multiple actions.

Real-life example: a shopping cart with ADD_ITEM, REMOVE_ITEM, CLEAR_CART and UPDATE_QUANTITY. Instead of many useState calls, one reducer handles every action.

  • state: the current state.
  • dispatch: sends an instruction (action).
  • reducer: the function that decides how state changes.
  • initialState: the starting value.

Remember what the reducer returns: return state + 1; gives a number, return { count: state + 1 }; gives an object. It must return the same kind of thing as the initial state.

useEffect vs useLayoutEffect: what is the difference?

useLayoutEffect runs first, before the browser paints the screen. useEffect runs second, after the UI is on screen. Open the console and check the order.

Use useEffect almost always (API calls, timers, listeners). Use useLayoutEffect only when you must measure or move a DOM element before the user sees it, to avoid a flicker.

Data flows down by props. When two components need the same data, keep the state in their common parent and pass down the value and the function that changes it.

How to make pagination?

Keep only the current page number in state. The visible items come from slice, and the page count from Math.ceil.

Formula to remember: start = (page - 1) * perPage, end = start + perPage. When the search text or a filter changes, call setPage(1), or the user may land on a page that no longer exists.

How to combine search, filter, sort and pagination?

The order matters: search, then filter, then sort, then paginate. Each step uses the output of the previous one.

How to make a sortable table (click a column header to sort)?

Store two things: which column is sorted (sortKey) and the direction (sortDir). Clicking the same header flips the direction, clicking a new header starts at ascending. The arrow in the header shows the current state, and a checkbox column works as in the earlier Select all section.

Numbers are sorted with x - y, text with localeCompare. Dates written as 2026-10-12 (year first) sort correctly as text. For other date formats, compare new Date(x) - new Date(y).

With search and pagination, keep this order: search, filter, sort, then slice for the page. Otherwise only the visible page gets sorted. Call setPage(1) when the sort changes. Because columns is an array, adding a column means adding one line.

Which common React mistakes should I avoid?

  • Changing state directly. todos.push(x) or user.name = "A" will not re-render. Use the setter with a new array or object.
  • Missing or bad key in map. Use a unique id, not a random number or (for changing lists) the index.
  • Hooks inside if, loops or normal functions. Call hooks only at the top level of a component or custom hook.
  • Wrong dependency array. Missing values give stale data. Setting state inside useEffect with no array causes an infinite loop.
  • async directly on the useEffect callback. Create an async function inside it and call it.
  • Calling the handler instead of passing it. onClick={handle()} runs immediately. Write onClick={handle} or onClick={() => handle(id)}.
  • Forgetting e.preventDefault() in a form submit, so the page reloads.
  • Not cleaning up timers, listeners or subscriptions in the useEffect return function.
  • Storing derived data in state (like a filtered list). Compute it during render.
  • Forgetting res.ok after fetch.

Ternary operator: how to use it in React

The ternary operator is a short if / else that works inside JSX. The format is condition ? valueIfTrue : valueIfFalse. You can chain more than one ternary to check several conditions, and you can mix it with && for boolean checks.

Read it from top to bottom. If timeOfDay is 'morning' it shows Good Morning, else if it is 'afternoon' it shows Good Afternoon, else it shows the last value (Add Greeting...).

Use a ternary when you need both an if and an else result. If you only need to show something when a condition is true, {loggedIn && <h2>Welcome</h2>} is shorter. Keep chains to two or three levels, and if it gets hard to read, move the logic into a normal if above the return.

Local Storage example: form with 4 fields

Local storage keeps small data in the browser, so it is still there after a refresh or after closing the tab. It stores only text, so use JSON.stringify to save an object and JSON.parse to read it back. In this form, the 4 fields live in one state object. The initial value is read from local storage, and a useEffect saves it again every time the object changes.

useState(loadForm) passes the function so React runs it only on the first render. Writing useState(loadForm()) would read local storage on every render. After handleClear runs, the useEffect saves the empty object again, so the key comes back with empty values. That is fine, but if you want the key gone, skip the useEffect save when the form is empty.

Check it in the browser: open DevTools, go to Application, then Local Storage, and you will see the profileForm key update as you type. Never store passwords or tokens you must protect here, because any script on the page can read local storage.

Local Storage basic example: save one name

Start here if local storage is new to you. There are only three commands: setItem("key", "value") to save, getItem("key") to read, and removeItem("key") to delete. The value is always text. In this example, type a name, click Save, then refresh the page. The name is still there.

How it works: the typed text lives in state (name). Local storage is only updated when you click Save. On refresh, state is lost, so useState starts from getItem and the saved name comes back.

To save a number, array or object, convert it first with JSON.stringify and read it with JSON.parse. See the form example above.

How to add React Icons

React Icons gives you thousands of ready-made icons as React components. Install it once, then import only the icons you need and use them like normal tags. Browse and search all icons at react-icons.github.io/react-icons.

The part after react-icons/ is the icon pack: fa is Font Awesome, md is Material Design, and so on. The icon name must start with the same letters, like Fa... for react-icons/fa. Copy the exact name from the website.

You can import several icons from the same pack in one line: import { FaShoppingCart, FaUserCheck } from "react-icons/fa";. Icons take the text colour and size of their parent, or you can set size and color props, for example <FaShoppingCart size={30} color="teal" />.

How to add, update and delete items in an array (state)

Never change a state array directly (no push, no splice). Always give the setter a new array: spread to add, map to update, filter to delete.

Put the key on the <li> and render one <ul> around the whole list. A <ul> per item, or a list inside an <h1>, is invalid HTML.

Using the name as the key only works while names are unique. Clicking Add twice creates two "Ketan" items with the same key, which gives the duplicate key warning. For real apps store objects like { id: 1, name: "Alex" }, use key={f.id} and filter or map by id.

map, filter, find: the daily three

map and filter always return an array, so you can chain them: products.filter((p) => p.inStock).map((p) => <li key={p.id}>{p.name}</li>) shows only the items in stock.

some, every, includes, findIndex: yes/no questions

reduce: many items into one value

Always pass the start value (the 0 or {} at the end). Without it, reduce uses the first item as the start, and it crashes on an empty array.

sort, slice, join, flat, Array.from

Methods that change the original array

These are fine in plain JavaScript but not on a React state array, because React will not see the change:

  • push, pop, shift, unshift, splice, sort, reverse

Common mistake: using map only to run code (no return value). Use forEach for that, or better, a normal event handler. Use map when you need the new array. Also remember that find returns undefined when nothing matches, so write product?.name before using it.

How to update state of an array of objects

To change one field of one object inside a state array, use map. For the object you want, return a copy with the new value ({ ...p, name: "New" }). For all other objects, return them as they are. Then give the new array to the setter.

Two things to get right: map over the state (items), not the starting array, and spread the single object (...p), not the whole array. Writing { ...products, name: "Bookish Me" } spreads the array into the object and creates keys 0, 1, 2 instead of id, price and so on. Mapping over the starting array instead of the state also loses earlier changes: a second update would start again from the original data.

Update by id from a function

In real projects each row has its own button, so pass the id (and the new value) into the handler. A small helper keeps all updates the same shape.

{ ...p, ...changes } copies all old fields, then the new ones overwrite them. The updater form setItems((prev) => ...) always starts from the latest state, which is safer when several updates happen quickly.

Add and delete an object

Do not change the object directly, like items[2].name = "Bookish Me", then call setItems(items). The array and the object are the same ones as before, so React sees no change and may not re-render. Always create a new array and a new object.
